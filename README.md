# 半格相机照片自动切割工具

将一张同时包含左右（或上下）两幅半格画面的扫描照片，自动定位两幅画面之间的片基间隙，
并分割为两张独立照片。

- 待处理照片置于 `input` 目录
- 切割结果写入 `output` 目录
- `input` 目录仅作读取：本工具不修改、不移动、不删除任何原始文件

半格相机（Olympus Pen、Kodak Ektar H35、Yashica Half 等）拍摄的画幅为 18×24mm，
冲扫服务常将相邻两幅扫描在同一个文件中。本工具用于将此类文件还原为两张独立照片。

---

## 一、目录规则

工具自动识别 `input` 目录中的子文件夹，并在 `output` 目录中生成同名文件夹：

| 输入目录中的内容 | 输出结果的位置 |
| --- | --- |
| `input/IMG_0001.jpg`（照片置于根目录） | `output/IMG_0001_1.jpg`、`output/IMG_0001_2.jpg` |
| `input/第一卷/`（整个文件夹放入） | `output/第一卷/` 中的同名结果 |
| `input/第一卷/夜拍/`（多层嵌套） | `output/第一卷/夜拍/`，目录结构完整镜像 |
| 照片与文件夹混合放置 | 分别归入对应文件夹，互不影响 |

```
input/                        output/
├─ IMG_0001.jpg      -->      ├─ IMG_0001_1.jpg   IMG_0001_2.jpg
├─ 第一卷/                     ├─ 第一卷/
│  ├─ 000001.jpg     -->      │  ├─ 000001_1.jpg   000001_2.jpg
│  └─ 000002.jpg     -->      │  └─ 000002_1.jpg   000002_2.jpg
└─ 第二卷/夜拍/                 └─ 第二卷/夜拍/
   └─ 0100.jpg       -->         └─ 0100_1.jpg   0100_2.jpg
```

- 带切割线的预览图保存于**结果所在目录**的 `_debug` 子目录，例如 `output/第一卷/_debug/`
- 如不需处理子文件夹，可加参数 `--no-subdirs`，或在图形界面中取消勾选"识别子文件夹"
- 输入目录中的非图片文件（如 txt）将被忽略，不影响处理结果
- 也可通过参数指定其他目录，完全不涉及 `input` 与 `output`：

```bat
python half_frame_splitter.py -i <输入目录> -o <输出目录> --debug
```

## 二、使用方式

### 1. 图形界面（推荐）

运行 **`运行-图形界面.bat`**，在窗口中选定目录后点击"开始处理"。

- 输入目录与输出目录默认为本工具目录下的 `input` 与 `output`
- 进度条显示处理进度，日志区显示每个文件的结果及其所属文件夹
- 处理结束后列出结果所在的全部文件夹，并询问是否立即打开输出目录
- 各项选项自动保存，下次启动时沿用上次设置

### 2. 命令行批处理

运行 **`运行-命令行.bat`**：将 `input` 目录中的照片（含各子文件夹）自动切割至
`output` 目录中的对应文件夹。

### 3. 命令行（可附加参数）

```bat
python half_frame_splitter.py                    :: 处理 input 目录，结果写入 output 目录
python half_frame_splitter.py --trim --debug     :: 去除扫描边框，并输出预览图
python half_frame_splitter.py --no-subdirs       :: 仅处理输入目录根层
python half_frame_splitter.py -i <输入目录> -o <输出目录>
python half_frame_splitter.py --dry-run          :: 仅识别，不写入文件（处理大批量前建议先执行）
```

## 三、命令行参数

| 参数 | 说明 |
| --- | --- |
| `-i, --input` | 输入目录，默认为 `./input` |
| `-o, --output` | 输出目录，默认为 `./output` |
| `--no-subdirs` | 仅处理输入目录根层，忽略子文件夹（默认识别子文件夹并生成同名文件夹） |
| `--orient auto\|lr\|tb` | 画面排布：`auto` 自动判断（默认）、`lr` 左右两幅、`tb` 上下两幅 |
| `--edge gap\|center` | 间隙处理：`gap` 整段舍去间隙（默认，画面不残留黑边）；`center` 自间隙正中切开 |
| `--trim` | 去除四周纯黑或纯白的扫描边框（适用于含片基边框的整卷扫描） |
| `--aspect off\|auto\|数值` | 按画幅比例居中裁剪，例如 `--aspect 0.75`（半格竖构图宽高比） |
| `--frame-aspect` | 单幅画面宽高比，默认 `0.75`（即 18:24） |
| `--search LO HI` | 间隙搜索范围（比例），默认 `0.22 0.78`，间隙显著偏移时可调整 |
| `--cut 位置` | 手动指定切割位置：`0~1` 为比例，大于 `1` 为像素 |
| `--format same\|jpg\|png\|tif\|webp` | 输出格式，默认与输入一致 |
| `--quality` | JPEG/WEBP 质量，默认 95 |
| `--overwrite` | 覆盖已存在的输出文件（默认遇同名文件跳过写入） |
| `--skip-uncertain` | 置信度不足时跳过该文件 |
| `--min-confidence` | 置信度阈值，默认 2.0 |
| `--debug` | 在结果所在目录的 `_debug` 中输出带切割线的预览图 |
| `--dry-run` | 仅执行识别，不写入任何文件 |
| `--recursive` / `--keep-structure` | 旧版参数，该行为现为默认，保留以兼容原有调用方式 |

输出文件命名规则：`原文件名_1`（第一幅：左或上）、`原文件名_2`（第二幅：右或下）。
原文件的 EXIF、ICC 色彩描述与 DPI 信息一并保留（方向标记已归一化，不会重复旋转）。

## 四、识别原理

本工具仅依赖 Pillow 与 numpy，不需要 OpenCV。

1. **多尺度条带检测**：在灰度剖面与色度剖面上滑动"中心条带与左右两侧条带对比"的检测器，
   定位狭窄、均匀且与两侧明显不同的条带。间隙既可暗于周围（正片扫描、冲扫店 JPEG），
   也可亮于周围或偏橙（负片片基）。
2. **均匀度加权**：实际间隙沿长度方向高度均匀，画面内的强竖线（如栏杆、门框）则不然，
   因此后者会被相应扣分。
3. **几何约束**：半格画幅为 18×24mm，两幅并排总长为 24mm × 1.5。据此推算切割位置的
   合理范围，并检验两个分块的比例是否合理。
4. **稳妥处理**：整图长宽比接近 3:2 时，两幅画面必然等宽，切割位置唯一确定于图像中心，
   此情况下偏离中心需要更强的证据支持；证据不足时按中心线切割，并在日志中提示。
5. **可选后处理**：`--trim` 去除四周纯黑或纯白的扫描边框；`--aspect` 按画幅比例修正构图。

切割位置在间隙内侧保留 15% 余量，以确保不切入画面内容。

## 五、常见问题

**问：切割位置不准确，或两张照片比例异常。**
答：加 `--debug` 运行一次，打开结果目录中的 `_debug` 查看预览图：红线为实际切割位置，
绿框为检测到的间隙。若日志提示"未检测到明确间隙（已按中心线分割）"，可：
- 使用 `--cut 0.5` 一类数值手动指定切割位置；
- 或重新扫描时将两幅画面连同中间间隙一并扫入（请勿裁去间隙）。

**问：何种情况下识别会失效。**
答：当画面严重过曝或漏光，导致间隙在图像上已不可分辨时，程序将退回中心线并输出提示，
不会强行切割画面内容。此类文件建议人工确认。

**问：照片为上下排布（扫描时方向旋转）。**
答：程序通常可自动判断；如不确定，可用 `--orient tb` 强制指定。需注意上下排布扫描得到
的单幅照片方向为横向，可在看图软件中旋转至正常方向。

**问：使用平板扫描仪自行扫描整卷，含黑边与齿孔。**
答：使用 `--trim` 去除四周黑边，并配合 `--debug` 检查效果。

**问：日志提示"原图比例接近 3:4，若该文件本身即为单幅画面"。**
答：半格单幅为 3:4（或 4:3），与两幅并排的 3:2 不同。若该文件本身即为已切割完成的
单幅照片，建议移出输入目录；否则说明扫描时裁剪较紧，可用 `--debug` 确认。

**问：支持哪些文件格式。**
答：jpg、jpeg、png、tif、tiff、bmp、webp、ppm、pgm、gif（扩展名大小写均可）。
16 位 TIFF 亦支持，分析时会自动拉伸。超大扫描文件同样可处理。

**问：是否会影响原始文件。**
答：不会。程序仅读取输入目录、仅写入输出目录，代码中不含任何删除或移动操作。遇同名
输出文件时默认跳过写入，如需覆盖可加 `--overwrite`。

**问：处理大量文件时的耗时。**
答：单张约 0.2 秒（以 2000×1300 计），数百张通常在一至两分钟内完成。图形界面在处理
期间不会失去响应，可随时中止。

## 六、自检

```bat
python selftest.py
python selftest.py --photos <照片A> <照片B>    :: 指定真实照片作为测试素材
```

自检将合成 19 类典型情形（黑、白、橙色间隙，上下排布，带黑边，含齿孔，重度 JPEG 压缩，
极细间隙，画面内含强竖线干扰，无间隙，低纹理内容等），逐项检验切割位置误差，并验证
端到端写入、单幅画面提示与**文件夹镜像**（根目录、A、A\B、B 四种层级）。样本、预览图与
切割结果写入 `_selftest` 目录。当前版本 19/19 通过；实际间隙的置信度为 3.0~12.3，
干扰项不高于 1.4（判定阈值 2.0）。

## 七、文件说明

| 文件 / 目录 | 用途 |
| --- | --- |
| `input/` | 待处理照片或照片文件夹（仅读取，不修改） |
| `output/` | 切割结果；子文件夹与输入同名，`_debug` 为预览图 |
| `half_frame_splitter.py` | 核心算法与命令行入口（可被其他脚本导入） |
| `gui.py` | 图形界面 |
| `selftest.py` | 自检脚本 |
| `check_env.py` | 启动前环境检查 |
| `运行-图形界面.bat` | 启动图形界面 |
| `运行-命令行.bat` | 直接执行 input → output |
| `安装依赖.bat` | 安装 Pillow 与 numpy |
| `_selftest/` | 自检产生的样本与预览，可随时删除 |
| `_gui_settings.json` | 图形界面保存的选项，可随时删除 |

运行环境要求：Python 3.8 及以上版本，并安装 Pillow 与 numpy 两个库
（可运行 `安装依赖.bat` 或执行 `python -m pip install -r requirements.txt`）。
